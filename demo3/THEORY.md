# THEORY · Demo 3 台账界面

本文件列出 Demo 3 依据的理论、已知极限与可证伪点，行号对应 `docs/THEORY_REVIEW.md`（即 `docs/PRD_v3.md` 第 1 节的审查表）与 PRD 第 0 节的"三层对应"表。
文中只写"依据"，不写"证明"：模拟数据上走通一条链路，不能替代真实数据上的检验。具体数值见 `report.html` 与 `RUN.json`。

## 1. 现金层：影子运行的逐头一致率

- **对应的行**：PRD 第 0 节"现金"行（圣农的选种闭环 → 影子运行逐头一致率 ≥ 99% → 依据：ssGBLUP 的确定性复现）；
  THEORY_REVIEW 第 1 行"基因组育种值可以用固定 SNP 面板准确预测"（Meuwissen, Hayes & Goddard 2001；VanRaden 2008 GRM；Legarra, Aguilar & Misztal 2009 ssGBLUP）。
- **本 demo 怎么用**：GBLUP / RR-BLUP 是闭式解（混合模型方程的解唯一），给定同一份基因型、表型与方差组分，任何正确实现都应逐头给出同一个 GEBV。
  `build.py` 用独立代码按同一公式（λ = 2Σpq·(1−h²)/h²）重新求解每一代参考群，与 refpop-agent 落盘的 `gebv_refpop.csv` 逐头比对，报告一致率与前 10% 名单重合度。
- **已知极限**：
  - refpop-agent 用的是 GBLUP（只含已分型个体），不是 ssGBLUP；真实场景要纳入未分型个体的系谱信息（H 矩阵），逐头一致还取决于系谱版本、固定效应与方差组分是否对齐。
  - 这里比对的是"同一方法的两份实现"，不是和客户现有软件比对；一致率高说明可复现，不说明模型好。
  - 准确度上界 r² ≈ N·h² / (N·h² + Me)（Daetwyler 2008；Goddard 2009）约束的是 r，不是一致率。
- **可证伪点**：任何一头的 |ΔGEBV| 超过容差，或前 10% 名单不重合，即视为不可复现，需要查数据版本或实现差异。

## 2. 为什么台账有 `randomized_control` 字段：相关不等于因果

- **对应的行**：THEORY_REVIEW 第 4 行"相关不等于因果：产业观察数据能支持决策改进"（观察数据的混杂，Pearl 2009 do-演算；育种界靠随机化配种与对照群处理）。
  该行的可证伪点原文即"Demo 3 台账预留'随机对照配种'字段"。
- **本 demo 怎么用**：台账记录"推荐 → 是否采纳 → 子代结果"。育种员是否采纳一条建议，本身会受个体条件、棚舍、批次等因素影响，
  因此"采纳组 vs 未采纳组"的子代差异是描述性的，`v_realized` 视图的注释也写明"descriptive only: adoption is not randomised"。
  `randomized_control = 1` 标记的是按随机分配执行的配对；只有这一部分的对比才能读成因果效应。
- **在模拟中的状态**：G1 推荐里按种子 15 抽取约 10% 打上该标记，仅为**占位**，演示字段可写、可在视图中分组；模拟器并没有据此改变配种。
- **已知极限**：场区、批次、年份的混杂可以制造虚假的"采纳有效"；样本量小（本模拟里被采纳的配对极少）时，即使随机化也只能给出很宽的区间。
- **可证伪点 / 升级路径**：如果真实台账里采纳组与未采纳组的差异在随机对照子集里消失，说明混杂主导；按该行的建议，向客户提议一轮随机化对照配种，这是台账升级为实验的路径。

## 3. 前向验证与 LR 法

- **对应的行**：THEORY_REVIEW 第 5 行"前向验证、配对增量、负对照能审计任何排序算法"（LR 法，Legarra & Reverter 2018：相关、偏差 μ、离散度 b；置换检验；亲缘泄漏，Habier 2007）。
- **本 demo 怎么用**：
  - 前向 r：用上一代为止训练的模型预测本代真实表型（`history.json`、`predictions.csv`），并由 `build.py` 逐个体复算；G0 没有上一代，只有 5 折 CV 基线，口径不同，报告中单独标注。
  - LR 统计：以上一代模型对本代个体的预测为"部分数据 GEBV"，以并入本代表型后重训模型的 GEBV 为"全量 GEBV"，计算偏差 Δ、离散度 b = cov(ĝw, ĝp)/var(ĝp) 与两者相关 ρ。
- **已知极限**：两个模型用各自训练群的等位基因频率中心化，Δ 混入了中心化差异，只作参考；只有两代可做前向比对，单次实现的抽样噪声（验证群 n=500）不可忽略；
  本 demo 只有一个模型，不涉及挑战者与多重检验校正。
- **可证伪点**：b 明显偏离 1（膨胀或压缩）、或前向 r 明显高于准确度上界（提示泄漏），都应在台账里触发复查。

## 4. 验证带宽（PRD 第 0 节约定）

`bandwidth = samples_per_year / label_latency_years` 是 PRD 第 0 节对每个 demo 的统一口径，不是一条理论。
Demo 3 取两条明示假设：一批 = 一个世代 ≈ 1 年；标签延迟 = 1 个世代（推荐的结果要等子代表型回流）。
模拟 manifest 的日历日期与"一代 ≈ 1 年"不一致，报告里给出了按日历折算的对照值。
