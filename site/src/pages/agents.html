育种的人这样读：把 AI 想成四个各司其职的助手：一个提想法（遗传学家），一个把想法写成可执行的计算（构建者），一个专门挑刺、拦下偷看未来数据的想法（评审者），一个事后总结（分析师）。他们谁都不能直接改育种方案，方案的每一步变化都要过六道门。
做 AI 的人这样读：四个角色对应提示词 P1–P5，输出必须符合 JSON schema；只能调用确定性工具（GRM、BLUP、LD、注释），产出候选与假设，不产出数字。评审者的泄漏扫描在写代码前就拦截"用了 selection_date 之后信息"的假设；去重按 DSL 的语义哈希；预算按 token 与全量评估数双重封顶。下面的回放来自真实的 events.jsonl 与台账。
董事会这样读：假设生成已经很便宜，稀缺的是验证。这一页证明两件事：AI 提出的想法能被一道道门拦住（这次回放 {{d0.proposals}} 个提案、{{d0.evaluated}} 次全量评估、{{d0.promoted}} 个晋级），以及每一次拒绝都留下了可审计的理由——这就是"裁判是产品、数据是资产"。

四个角色，一条铁律

遗传学家 · 提出

读数据目录与台账摘要，提出一个机制明确、方向明确、可证伪的假设，并写成算子计划（DSL）。

能看：数据字段、可用先验、台账里试过什么。不能看：封存世代、任何表型的未来值。

构建者 · 实现

把算子计划变成可执行的 DSL，附数据声明（每个字段何时可得）和四项自检（语法与单位、因果、重放确定性、边界情况）。

缺算子时返回"需要新算子"，不能自己发明数据。

评审者 · 挑刺

在假设阶段和代码阶段各审一次：时间泄漏、亲缘泄漏、结构泄漏、论点与代码不符、离散度风险。

它是第一道门，也是"Agent 可靠性"指标的来源：故意设计的泄漏探针必须全部拦下。

分析师 · 总结

评估之后写人话：哪道门卡住了、差多少、下一个最值得试的实验是什么。

它的总结进入每日摘要与 BreedingPackage，不改变任何状态。

铁律：agents 只能推荐，候选的状态只能由六道确定性门改变（有效性、准确度、配对增量、方案层、稳健性、研究门）。回放里橙色的"门槛"步骤就是这些状态变化；它们不是 AI 说了算，而是数字说了算。

按"播放"看整条链自动走；按"下一步"一步一步看；用"只看"筛选某个角色。左边是时间线，右边是当前这一步的原始内容（假设全文、评审证据、DSL、每道门的数值与阈值、分析师总结）。下方的漏斗随进度更新。

看的时候留意三件事：评审者退回构建者的理由（论点与代码不符、λ 缩放过激）；每次全量评估后"配对 ΔOOS 的 90% 下界"是不是大于 0——这次回放里没有一个候选做到；以及分析师建议的"下一个实验"总是台账里还没出现过的机制簇，这就是假设工厂不原地打转的机制。

为什么"0 晋级"是好消息

裁判在工作

这次回放里 {{d0.evaluated}} 个走完全部门槛的候选没有一个在冻结冠军之上做出可复现的增量；Demo 1 全程（模拟 + 猪数据）挑战者晋级 {{d1.promoted_total}} 个、负对照误晋级 {{d1.neg_sim}} / {{d1.neg_pig}} 次。审查表第 6 行早就写了：线性模型在大样本上难以被超越。

每次拒绝都是资产

被拒的想法、拒绝的门、差了多少，全部进台账。下一轮遗传学家读到台账摘要时，会避开试过的机制簇，转向没试过的——便宜的假设变成了不重复的搜索。

带宽才是瓶颈

假设一分钟能出十个，全量评估一次要跑一遍前向验证；一个世代之后才知道对不对。所以我们把力气花在验证带宽与裁判上，而不是花在"更会提想法的模型"上。这也是 自驾育种 what-if 的出发点。

智能体与四个 Demo 的关系

Demo智能体在这条线上做什么裁判审什么
Demo 1 裁判（育种）C 臂：只提一次假设；D 臂：完整闭环（提出 → 评审 → 实现 → 评估 → 总结 → 再提出）育种值排名能否在配对增量门上胜过冻结 ssGBLUP

Demo 3 台账不直接参与：台账记录的是人的决策与结果；agents 只读它的摘要逐头一致率；采纳与结局
Demo 4 审计同一套角色换成"肽段特征组合"的假设；留患者验证top-20 命中率的配对增量；负对照零晋级
Demo 5 自驾育种假设工厂 + 自动化湿实验 = 闭环不需要人在中间传递；带宽决定一切提案越多，多重检验校正越关键
