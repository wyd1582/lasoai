台账浏览器

这就是客户会看到的东西：搜一头动物或一条建议编号，点任何一行，看它的排名、分数、建议动作、是否被采纳，以及一个世代后回流的子代数与 42 日龄均重——一条建议从发出到结果的追溯链。每一行都是台账的原始记录。
诚实的发现：采纳率只有 {{d3.adopt_g0}} / {{d3.rec_g0}} 与 {{d3.adopt_g1}} / {{d3.rec_g1}}，因为模拟器选亲本时不读选配建议。这是模拟器的行为，不是对真实采纳率的估计。下一步是让选配节点真正驱动模拟器的亲本选择；再往后是接客户流程。

验证带宽

bandwidth = samples_per_year / label_latency_years = {{d3.samples_per_year}} / {{d3.latency}} = {{d3.bandwidth}}。假设一批 = 一个世代 ≈ 一年、标签延迟一个世代。若按模拟批次的实际到货间隔折算（约 98 天一批），样本/年约 {{d3.bandwidth_calendar}}。Deck 的口径：产业以百万级样本/年计，实验室以千级实验/年计；我们的护城河是时间，他们的是算力。

商业含义

A 线 · 育种智能体

本地部署的选种闭环，部署费 + 年费。本页就是交付物的骨架：七步流程、逐头可查、每步可复现。

B 线 · 数据平台与台账

平台费 + 按样本。台账每过一个世代多一层带标签的数据；后来者从第一天起就落后三个世代。留存假设 ≥ 90%，因为台账即切换成本。

复利三环

数据环（标签随世代累积）、内容环（台账告诉我们哪些位点反复贡献预测力 → 下一代面板）、信任环（可复现、可审计的记录被客户与主管部门采用）。三环的起点都是这三张表。

现金层的两个数字怎么来："逐头一致率 ≥ 99%"的机制是本页的独立重算（{{d3.agree}} / {{d3.agree_n}}，最大差 {{d3.max_diff}} 克）；"交付 ≤ 4 周"的机制是管线一条命令重建（本 demo {{d3.seconds}} 秒）。两个数字变成真实承诺，只差客户数据的影子运行。
